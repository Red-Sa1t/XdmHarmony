## 3. 关键算法翻译说明

### 3.1 闭窗响应校验链（closedWindowValidationError，PieceGrabber.cs:181-202 三方对照）

源码 `Connect()` 收到响应后的处理序（逐字）：

```
:181-188  response.Compressed → contentLength=-1；statusCode==206 → status=OK(200)
:194-196  !firstRequest && status!=206 → NonRetriable(InvalidResponse,"Resume not supported :: id")
:197-201  !firstRequest && contentLength>0 && IsFileChangedOnServer(StreamType, ContentRangeLength, null)
            →（:512-516 FileSize>0 ? FileSize!=streamSize : false）
          → true 则 NonRetriable(InvalidResponse,"Content length mismatch :: id")
:203-204  maxByteRange = contentLength<=0 ? -1 : piece.Offset+contentLength
```

ArkTS 纯函数按调度器现实现（PieceGrabber.ets:673-691）逐字抽离，检查序与源码一致：

```
eff = effectiveProbeStatus(status, compressed)     // compressed 206→200 改写前置（源码 :181-188 在检前）
eff !== 206                        → CWV_STATUS    // :194-196
fileSize > 0 && total !== fileSize → CWV_TOTAL     // :197-201；gate=FileSize>0（:512-516 return false）
contentRangeStart !== windowStart  → CWV_START     // U1.2 D9 加固（源码无）
否则                               → CWV_OK
```

要点：
- **compressed 改写使 206 断点续传禁用**：`closedWindowValidationError(206, true, …)` 返回 CWV_STATUS（改写后 200≠206）——这是原版"compressed 响应不可续传"的锁面（连带 ResourceSize=-1、maxByteRange=-1，:181-188 连锁）。
- **total 比对值是 Content-Range 头的 total**（`ContentRangeLength=GetTotalLengthFromContentRange`，DotNetHttpSession.cs:94-98），不是响应体 ContentLength；缺头=-1。源码外层门 `contentLength>0` 是**响应体字节数**（非 compressed 206 恒>0，空 206 退化响应极罕见）——ArkTS 链省略该门（D24）。
- **Content-Range 缺失 → CWV_TOTAL**（fact 1 修正，§0-2）：total=-1≠FileSize>0 → mismatch。

### 3.2 探测面推导（CreateProbeResult，PieceGrabber.cs:436-447 + 调度器 probeConnected）

```
:440  ResourceSize = response.Compressed ? -1 : response.ContentLength
:441  Resumable     = response.Compressed ? false : status == 206
```

- `effectiveProbeStatus`：改写规则抽离（compressed&&206→200；其余透传）。探测与闭窗共用（调度器 :650-653 先算 eff 再分支）。
- `probeResumable(compressed,status)`：= `!compressed && status===206`（:441 逐字；调度器 :725 splittingAllowed、:729 resumable 两处内联同式，:725 额外 `&& totalSize>0` 由调用方组合，不在函数内）。
- `probeTotalSize(compressed,contentLength,contentRangeTotal)`：`compressed → -1`；否则 `contentLength>0 ? contentLength : contentRangeTotal`。fallback 分支是 U2.1 既有加固（调度器 :709-713：CL 缺失/0 时落 Content-Range total；源码 :440 无 fallback，其 206 响应 CL 恒在）——用例按**调度器行为**锁定并注明（§4-D24 同族）。

### 3.3 恢复偏移数学（AddRange/Seek/读长，PieceGrabber.cs:387-395 + :169-170 + :203-204 + :284-285）

- **Range 头两形态互斥**（既有 `windowOf` 已测，本单元补头锚与端点）：
  - 首请求 `AddRange(0)` → `bytes=0-`（:389；WebRequestExtensions.cs:168-177 单参 open-ended）→ `resumeRangeHeader(offset)`；
  - 非首请求 `AddRange(Offset+Downloaded, Offset+Length-1)` → `bytes=S-E` 闭区间含端点（:394；WebRequestExtensions.cs:160-163）→ `closedRangeHeader(start,end)`；写盘 `Seek(Downloaded, Begin)` → **恢复起点=绝对 Offset+Downloaded**（与 windowOf 的 [O+D, O+L-1] 同源）。
  - 端点边界：downloaded=0 → 窗=[O, O+L-1]；downloaded=L-1 → 单字节窗 [O+L-1, O+L-1]；downloaded=L → [O+L, O+L-1] 空窗（公式原样输出，getInactivePiece 排除项保证不派发——用例注明）。
- `isNonResumableResume(openWindow, pieceLength)`：源码 `piece.Length==-1 && !IsFirstRequest` → NonRetriable(NonResumable,"Resume not supported")（:169-170）；调度器形 `!openWindow && pieceLength<=0`（PieceGrabber.ets:426-427，D12 首请求≈开窗口/探测类派发）。锁定调度器形，差异登记 D20。
- `maxByteRangeOf(pieceOffset, contentLength)`：`contentLength<=0 ? -1 : pieceOffset+contentLength`（:203-204 逐字）。**运行时调用点等价论证（D23，COLD-F2 修正）**：调度器 :824 传 `record.windowEnd+1`（=Offset+Length）；本响应 contentLength=206 响应体字节数=窗口长度（Length-Downloaded连接时；DotNetHttpSession.cs:32 CL 头缺失时回落 ContentRange total=文件全长）——**两形相等仅当连接时 Downloaded==0**，Downloaded>0（窗口中断重派后续完成）时源形=Offset+Length-Downloaded 严格小于运行形。行为等价不依赖两形相等：pieces 不交覆盖下运行形恰=邻片 Offset、源形更小，吸收条件 (邻片O+邻片L)<=maxByteRange 要求邻片 L<=0 恒假——两形吸收均不可达；**原版例外（D6 有意差异完整边界）**：CL 头缺失回落全长时源形=Offset+fileSize 可越过邻片末端，原版闭窗吸收在该场景可达，ArkTS 运行形不复刻——纯函数按源码公式锁定，运行时零改动。
- `cappedReadLen(bufLen, remaining)`：源码每轮读长 `Math.Min(BUF.Length=32768, remaining)`（:284-285，BUF 定义 :259）；`remaining<=0` 在源码由 :270-279 先行分支消化（吸收/收尾），纯函数守卫返 0（ArkTS 防御，域内行为逐字）。运行时对应物是 worker 窗口余量封顶（SegmentWorker.ets:178-179 `remain=windowLen-written`）——机制映射而非同式，矩阵标"架构等价+纯函数锁源码形"。

### 3.4 分裂序列收敛（场景级锁定，CreatePiece 驱动节奏）

原版分裂节奏由"每连接成功"驱动（PieceConnected :205 → SingleSourceHTTPDownloader.cs:292 末尾无条件 CreatePiece），每次分裂净增一片直至阈值。既有用例锁定单次分裂数学，缺**序列级收敛**：4MiB 初始片经 findMaxChunk+splitPiece 循环 15 次 → 16 片×262144、`findMaxChunk→null`（rem==262144 不满足严格 `>`）。序列用例锁四个不变量：
1. **Σlength 恒定**=4194304（分裂只切不移）；
2. **覆盖连续无重叠**（按 offset 排序后 prev.offset+prev.length==next.offset）；
3. **downloaded 守恒**（分裂把 downloaded 留在下半区，Σdownloaded 不变）；
4. **终止性**（findMaxChunk 返 null 时片数=16）。

### 3.5 重试节奏（:98-124，phase 轴映射——不抽死函数）

源码 catch 链：HttpException 且 `Enum.IsDefined(HttpStatusCode, status)` → DownloadException(InvalidResponse) 终态；否则吞 → `timesRetried++`（:113）→ 超限 MaxRetryFailed（:115-116，先增后判=最多 11 次尝试）→ connectPhase 才 sleep(RetryDelay×1000)（:118-124）。ArkTS 映射：传输异常统一 `status=0 → phase='connect'`（SegmentWorker.ets:210），4xx/5xx 等 status 到手场景由响应校验链终态化（§3.1）——Enum.IsDefined 分类无对应物（D21）；connect/body 的 sleep 判据由结构承载（:794 retryConnectPhase 有 sleep、:838 retryImmediately 无 sleep，先增后判经 `exceedsMaxRetry` 已测）——判据不抽独立函数（D22）。

### 3.6 线程模型映射

本单元**零线程新增**：全部新纯函数是主线程同步调用面（Hypium 本地执行也在主线程）。被测两文件保持**零 @kit import**（U2.1/U1.2 既定纪律）——这是 Hypium 能直接加载的前提，也是本地单测与 TaskPool 运行时行为一致的保证（纯函数无 IO/无时钟/无并发态）。调度器/worker 的线程面（TaskPool+sendData 消息化，决策 2）本单元只读不改。

```ts
/** 闭窗校验结果码（§2.1 表；≠0 由消费方映射 ERR_INVALID_RESPONSE(5)——本单元不接线） */
export const CWV_OK: number = 0;
export const CWV_STATUS: number = 1;
export const CWV_TOTAL: number = 2;
export const CWV_START: number = 3;

/** compressed 改写（:181-188 逐字）：compressed 且 206 → 200；其余透传 */
export function effectiveProbeStatus(status: number, compressed: boolean): number {
  if (compressed && status === 206) { return 200; }
  return status;
}

/** 探测 Resumable（:441 逐字） */
export function probeResumable(compressed: boolean, status: number): boolean {
  return !compressed && status === 206;
}

/** 探测 ResourceSize（:440 + 调度器 :709-713 推导链）：compressed→-1；CL>0 优先，否则 Content-Range total */
export function probeTotalSize(compressed: boolean, contentLength: number,
  contentRangeTotal: number): number {
  if (compressed) { return -1; }
  return contentLength > 0 ? contentLength : contentRangeTotal;
}

/** 闭窗三检（:181-202 检查序 + U1.2 D9 start 检）：0=通过，CWV_STATUS/CWV_TOTAL/CWV_START=违规 */
export function closedWindowValidationError(status: number, compressed: boolean,
  contentRangeTotal: number, fileSize: number, contentRangeStart: number,
  windowStart: number): number {
  if (effectiveProbeStatus(status, compressed) !== 206) { return CWV_STATUS; }
  if (fileSize > 0 && contentRangeTotal !== fileSize) { return CWV_TOTAL; }
  if (contentRangeStart !== windowStart) { return CWV_START; }
  return CWV_OK;
}
```
