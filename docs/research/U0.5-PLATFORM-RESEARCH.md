# U0.5 平台能力调研结论（2026-09-27 夜间，主会话完成）

> 对照 MIGRATION_PLAN §3 降级清单与 §7 Phase 0 第 5 项。证据全部来自本机 `devecocli docs`（HarmonyOS 6.1.1(24) 本地文档）。

## 1. 托盘（原"视鸿蒙 API 调研结论，可降"）→ **GO 信号**

- **发现**：Desktop Extension Kit 的 `statusBarManager`（状态栏管理服务，起始版本 5.0.0(12) ≤ 目标 API 24）："应用可以通过接入相应的 API，快速在状态栏显示应用及下拉面板，实现对应用的管理；用户可以通过直接操作状态栏图标完成一些应用操作。"（API 参考/基础功能/Desktop_Extension_Kit/…/statusbar-extension-manager）
- **结论**：PC 托盘等价物存在，方向可行。具体接口面（注册图标/下拉面板/点击回调、是否需权限声明）在 U5.1 实装时按文档细化；若实装受阻，降级为"最小化到任务栏 + 后台长时任务保活"。
- 对原计划影响：§7 Phase 5 的"（视调研）托盘/自启"从待定转为 GO 倾向，写入 U5.1 验收备选项。

## 2. 开机自启（原"视调研，可降"）→ **半降级（维持）**

- **发现**：`@ohos.app.ability.autoStartupManager`（API 21+）仅提供**查询自身**自启状态（`getAutoStartupStatusForSelf`）；启用入口是**系统设置手动配置**（设置 > 应用和元服务 > 应用启动管理）。MDM 的 `addAutoStartApps` 仅企业设备管理可用，不适用。
- **结论**：不做代码实现；在设置页/交付报告中写明"通过系统设置开启自启"，可选在设置页加状态查询。与原降级清单一致，无需改动。

## 3. fs 随机写/追加写（U2.2 分片落盘的前提）→ **GO**

- **发现**：`fileIo.writeSync` 的 `WriteOptions.offset` 支持指定写入位置（随机写）；`fs.openSync(path, OpenMode.APPEND)` 支持追加打开。（faqs-local-file-manager-35 / -64）
- **结论**：分片文件"追加写 + 按 offset 写"两种模式都有原生支撑，U2.2 的落盘设计无需变通。U0.1 环境自检探针的写盘项已验证基本 fileIo 可用。

## 4. rcp（Remote Communication Kit）能力面 → **重大发现：TLS 降级项可能反转**

- **发现**：rcp 提供两种跳过/自定义证书校验机制（faqs-remote-communication-6）：① 自定义 `remoteValidation` ValidationCallback（返回 true 放行）；② 直接 `remoteValidation: 'skip'`。另外 faqs-network-127 确认 rcp 支持请求体传参与下载场景（`rcp.DownloadToFile` 等）。
- **影响**：原计划降级清单第 8 条"TLS 证书错误放行（鸿蒙不可设，自签证书站点将失败）"是基于 @ohos.net.http 的结论。**若 U0.2 探针定栈选 rcp，则自签证书站点下载可对等原版行为（原版全放行）**——降级项 8 可从清单移除，改为"已对等（rcp remoteValidation）"。
- **栈选型天平**：rcp 现在有两大优势（性能/配置更丰富 + TLS 放行能力），@ohos.net.http 的优势仅剩 API 更基础简单。**晨间 U0.2 探针若确认 rcp 在 TaskPool 内可用且流式回调行为满足，倾向选 rcp**。注意 faqs-network-127 提到 `rcp.DownloadToFile` 不支持请求体——但我们的下载引擎用流式回调自行落盘（不依赖 DownloadToFile），不受影响。
- 风险 #2（HTTP 能力）的退化路径成本下降。

## 5. 浏览器预装（模拟器/真机）

- 文档无法回答，属设备实测：晨间真机目检（用户清单第 6 项）。真机为华为设备，浏览器预装概率高；扩展栈实测随 Phase 6。
